# SMS Service

This project utilizes UNIFONIC (https://docs.unifonic.com/docs/sms-getting-started) and can be utilized by any micro-service that intends to send sms


## UNIFONIC parameters
###  Parameters that should be generated from Unifonic dashboard that any sender application should have

### Sender ID
Sender ID - also known as Alphanumeric Sender ID or just Sender is a string of up to 11 alphanumeric characters (e.g., DAWY-WASEEL) that would entirely replace a phone number. The benefit of using Sender ID is credibility, as your message would appear on the recipient's phone with your brand name.

### Application ID (AppSid)
The application ID is a mandatory authentication parameter in the API request. Having a Unifonic account, customers can create as many AppSid's as needed. Application IDs help differentiate traffic by verticals, users, and accounts/sub-accounts.

# SMS Service API documentation:
## REST API

To use waseel-sms-service REST API, you will need a Unifonic account, an application ID (AppSid), and a registered sender.

### The API request includes the following parameters:

| Parameter | Description | Value |
| :---------------: | :-------------: | :-----|
| appSid         | Authentication string that uniquely identifies your application         | 6v253153s1g7831s5 |
| senderID       | The SenderID identifies who has sent the SMS message                    | PBM-WASEEL, DAWY-WASEEL |
| appName        | The application name that sent the sms request                       | PBM  |        
| message        | Message body. Supports both English and Unicodes characters e.g. Arabic | Hello Hashim, we have received your prescription from Dallah hospital. Please click the link to view details. https://qa-pbm-admin.waseel.com/patient-prescription  |
| memberMobileNo | Destination mobile number                                               | Mobile numbers must be in one of these formats [+966504831270, 00966504831270, 966504831270]  |


### Sample SMS JSON Post Request:{{host}}/sms/send

# Security


> waseel-sms-service has a secured RESTful endpoint that receives the SMS request. <br>
> The service expects an access token in the HTTP request header. The access token is to be generated by **Waseel's Identity and Access Management (IAM)** server Keycloak.

### Sample SSO Token Details to be present in the sender *application.properties* file 
sso.url = https://qa-iam.waseel.com/realms/waseel-qa/protocol/openid-connect/token <br>
sso.auth.username:pbm-notification-service <br>
sso.auth.password: Kl5ToUwJYGCmngFDqsAj7AxjTslWt8t <br>
sso.content.type:x-www-form-urlencoded <br>
sso.body.key:grant_type <br>
sso.body.value:client_credentials <br>
